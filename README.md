# BSC 代币分发脚本

自动采集 BSC 近期交易过的地址，过滤重复地址和已有该代币余额的地址，再按配置分发代币。

**只有执行发送命令才会转账。脚本运行结束后退出。**

## 1. 安装与初始化

安装 Git 和 Node.js 22 的最新维护版本或更新的 LTS 版本。使用有仓库访问权限的账号获取代码，在 PowerShell 中执行，将 `<仓库地址>` 替换为实际 Git 地址：

```powershell
git clone "<仓库地址>" bsc-distributor
cd bsc-distributor
npm.cmd ci
```

如果已下载并解压代码，直接在项目文件夹打开终端，执行 `npm.cmd ci` 即可。后续所有命令都在项目文件夹内执行。

首次使用时，在项目文件夹中准备两个配置文件：

- 复制 `config.example.json`，将副本改名为 `config.json`，用于填写代币合约和发送参数。
- 复制 `.env.example`，将副本改名为 `.env`，用于填写节点和私钥。

如果这两个文件已经存在，直接编辑即可，不用重新创建。Windows 下注意文件名不要变成 `config.json.txt` 或 `.env.txt`。

## 2. 修改配置

打开 `config.json`。主要字段如下，保存后下次启动生效：

| 字段 | 示例值 | 含义 |
| --- | --- | --- |
| `chainId` | `56` | BSC 主网 |
| `tokenAddress` | `REPLACE_WITH_TOKEN_CONTRACT` | 要发送的代币合约；首次使用需替换示例占位符 |
| `countPerRun` | `50` | 每次运行最多处理的地址数，可自行增加或减少 |
| `amountPerAddress` | `"0.0001"` | 每个地址发送的名义代币数量 |
| `batchSize` | `5` | 每批广播数量，支持 1～5；设为 1 则逐笔确认 |
| `maxGasPerRunBnb` | `"0.002"` | 本次所有交易的手续费预留总预算，单位 BNB |
| `maxGasPriceGwei` | `"1"` | 单位 Gas 价格上限，单位 Gwei |
| `confirmations` | `15` | 发送后等待的确认数，也用于采集时避开最新区块 |
| `lookbackBlocks` | `500` | 最多回看多少个区块 |
| `rpcDelayMs` | `150` | 每个采集任务查询之间的等待毫秒数 |
| `collectConcurrency` | `3` | 同时检查的候选地址数，支持 1～5 |
| `confirmationTimeoutMs` | `120000` | 等待每笔交易确认的最长时间，单位毫秒 |
| `confirmationPollMs` | `2000` | 确认状态查询间隔，单位毫秒 |
| `timezone` | `"Asia/Shanghai"` | 记录日期的时区，不影响按次配额 |
| `excludeAddresses` | `[]` | 自行指定要排除的地址 |

JSON 不允许注释或末尾多余逗号；金额保留双引号。新增的采集并发和确认等待字段可省略，省略时使用表中的默认值。

**50 不是固定上限。** 每次重新启动都有独立配额；数量、候选地址、余额或预算不足时可能提前停止。恢复的旧待确认交易也计入本次数量和预算，例如恢复 1 笔后，本次最多再新发 49 笔。

`maxGasPerRunBnb` 是预算，不是固定扣款。脚本按每笔 `gasLimit × gasPrice` 累计预留，实际扣费取决于链上消耗；预算或余额不足以覆盖整批时，先发送能够负担的小批次，再停止。每个地址仍是一笔独立交易，分批广播不会直接降低手续费。

### 节点和私钥

`.env` 中 `BSC_RPC_URLS` 留空会使用内置主网公共节点。也可以填写逗号分隔的列表：

```dotenv
BSC_RPC_URLS=https://bsc-dataseed.bnbchain.org,https://bsc-dataseed-public.bnbchain.org,https://bsc-rpc.publicnode.com
PRIVATE_KEY=你的钱包私钥
```

节点超时或限流时会尝试备用节点，并对失败节点短暂退避。只读请求的链 ID 校验缓存 30 秒，广播前会重新校验。预览不需要私钥；真实发送时，在本机填写专用分发钱包的 `PRIVATE_KEY`。不要把文件保存为 `.env.txt`，不要上传或分享私钥。

钱包需要持有目标代币和原生 BNB。**BNB 用于支付手续费。**

## 3. 采集并预览（不转账）

```powershell
npm.cmd run preview
```

每 5 秒显示进度，完成后在终端显示候选地址、来源区块和来源交易。清单只保存在本次内存中，不写入 JSON 文件。一份清单内不会重复；多次预览可能出现相同地址。

## 4. 实际发送

填写私钥、准备好代币和 BNB 后执行：

```powershell
npm.cmd run send -- --execute
```

脚本会重新采集地址，不固定使用上次预览清单。每批先检查并保存签名交易，按连续 nonce 广播最多 5 笔，再等待这批确认，最后处理下一批。终端显示交易哈希，可在 BscScan 查询实际手续费及结果。退出时显示本次数量、各状态笔数、发送前跳过数量，以及已确认回执的实际 BNB 手续费。未能获得实际费用的完成记录计入 `unknownFees`，不会按零费用认定。

采集和准备发送时都会查询该代币余额：余额非零就跳过，查询失败不会当作零余额放行。合约地址、配置排除地址、未完成交易的地址和本次已处理地址也会跳过。不保留永久发送名单；如果地址后来将代币全部转走，后续运行可能再次向它发送。

采集地址不代表独立用户或接收意愿。特殊代币的手续费、黑名单、限频等机制可能影响实际到账或导致回滚。

### 只查看状态

```powershell
npm.cmd run status
```

查询当前配置链上的未完成交易，无需私钥，不签名、不广播，也不修改 `state.json`。`tokenAddress` 尚未填写时也可以查询已有记录。链上查不到交易时显示 `unknown`，这不代表交易一定没有广播。

### 仅恢复已有交易

```powershell
npm.cmd run recover -- --execute
```

只核对或重播当前代币已有的原签名交易，不采集新地址、不创建新付款。记录中已经保存签名，因此恢复不需要私钥，但可能实际广播交易并产生手续费。恢复使用记录里的原金额和发送方，仍受本次数量与手续费预算限制。

`send -- --execute` 仍会先恢复已有交易，再继续采集并发送新地址。如果只想处理上次中断的交易，请使用 `recover`。

## 5. 临时记录与中断恢复

执行顺序：**查询余额 → 签名并暂存交易 → 广播 → 等待确认 → 删除完成记录**。广播前先保存，是为了避免节点响应丢失或程序中断后重复付款。

| 文件 | 作用 |
| --- | --- |
| `data/state.json` | 仅保存未完成交易的签名、哈希和状态，用于中断恢复 |
| `data/run.lock` | 运行期间的进程锁，正常退出时移除 |

| 状态 | 含义 |
| --- | --- |
| `prepared` | 已签名并保存，尚未尝试广播 |
| `broadcasting` | 已开始尝试广播，结果仍需核对 |
| `submitted` | 节点已接收或查到交易，尚未达到确认数 |
| `confirmed` | 达到确认数且执行成功，从临时记录中移除，计入终端汇总 |
| `reverted` | 达到确认数但执行回滚，从临时记录中移除，报错并计入终端汇总 |

超时、停止或广播结果不明确时保留记录，下次使用 `send` 或 `recover` 核对原交易；不会另签一笔替代付款。只读的 `status` 不清理记录。

**存在未完成交易时，不要删除、清空或回退 `state.json`。** 全部处理完成后，文件只保留少量空状态信息，不随累计发送数量持续增长。不自动备份，也不保存永久收款地址名单。`confirmed` 表示链上执行成功，不保证特殊代币的实际到账数量。

## macOS / Linux 命令

进入项目目录后，安装依赖使用 `npm ci`，预览使用 `npm run preview`，发送使用 `npm run send -- --execute`，只查状态使用 `npm run status`，仅恢复使用 `npm run recover -- --execute`。

## 许可证与私钥保管

**私钥和助记词务必自行安全保管。不要发送给其他人或第三方服务，不要上传到代码仓库、日志或截图中。** `.env` 是本机明文配置文件，应限制访问并妥善保存；请使用独立分发钱包，仅存放必要的资产和手续费。
